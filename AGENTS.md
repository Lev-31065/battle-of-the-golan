# Battle of the Golan: project rules

## What it is
- A 2D top-down capture-the-flag game that runs in a phone browser. Hebrew vocabulary questions guard the key actions: buying weapons, grabbing flags and passing rocks.
- For teens playing together in the same room, each on their own phone. Built by Daniel, who is a beginner.
- Live: https://lev-31065.github.io/battle-of-the-golan/

## Tech stack
- Plain HTML, CSS and JavaScript. No build step, no npm, no frameworks.
- PeerJS 1.5.4 (from unpkg) for phone-to-phone connections.
- Supabase (supabase-js 2.49.4 from jsDelivr) for optional logins and saving progress online. Project URL + publishable key live in `account.js` (they're public by design; never add the secret/service_role key). Database setup: `supabase/setup.sql`.
- MyMemory (free, no key) auto-translates Hebrew → English in the deck editor. Settings in `TRANSLATE` (`rules.js`). About 5,000 letters a day free per computer. Mentioned on the privacy page.
- Rubik font from Google Fonts. Sounds are synthesized with Web Audio, so there are no audio files.

## Run, test, deploy
- **Run:** double-click `index.html`. To test multiplayer, open it in two browser windows and join one from the other.
- **Test:** there's no test framework, and Node isn't installed. To check changes, run headless Edge (`--headless=new`) with `--screenshot` or `--dump-dom`:
  - `requestAnimationFrame` doesn't tick under `--virtual-time-budget`, so test pages have to call `update()` themselves.
  - The headless window can't go narrower than 504px. Narrow screenshots look clipped even when the layout is fine.
  - For a real two-browser PeerJS test, run two headless Edge instances with `--remote-debugging-port` and have them POST results to a PowerShell `HttpListener`.
- **Deploy:** Git + GitHub CLI (`gh`, logged in as Lev-31065) are installed, so Claude can upload. The project folder itself is NOT a git repo: clone `Lev-31065/battle-of-the-golan` into the scratchpad, copy the changed files in, commit, push. Compare with `diff --strip-trailing-cr` first (line endings make every file look different). Pages serves `main` from the root folder and takes about a minute to update. (Daniel can still upload by hand: Add file → Upload files → Commit.)
  - **Before every upload, bump the version:** `GAME_VERSION` in `rules.js` AND every `?v=…` in `index.html` (style.css + the 16 scripts), to the same new value (e.g. 2026-11-10e → 2026-11-10f). Otherwise phones keep running old saved copies (Daniel's phone did). The home screen shows the version under Privacy, so Daniel can check.

## Folder structure
- `index.html`: all screens (home, play, lobby, HUD, shop, quiz, winner)
- `style.css`: looks
- `map.js`: map layout (rivers, bridges, dirt paths, bushes "berry"/"leafy", rocks, hollow logs, bases). Only the LEFT half is listed; `mirrorLeftHalf()` makes the right half, so the map is fair. Plus `isInWater`, `riverFlowAt`, `isInBush`, `logLocal`
- `rules.js`: every tweakable setting, plus shared helpers. `ITEMS` = the shop (cost in right answers, damage, range, cooldown, icon, Hebrew names; `kind` "melee" = Hit button, "throw" = Throw button with `perBuy`, `speed`, `freezes`, `goesThrough`, `lands` (grenade), "spear" = no button (tip touch), "plant" = Hit button becomes Plant (tree), "wear" = worn, not held, no toolbar button (boots; `isHoldable()`)); the shop and the toolbar list items in that order. `POMEGRANATE` = grenade + tree settings. `LOG` + `throwFitsLog()` = log rules. `GAME_VERSION` + `reportProblem()` live here too
- `sound.js`: sound effects and mute
- `speech.js`: reads words out loud with the phone's built-in voice (or a recording, if a word has `audio`), plus the word card at the top
- `levels-b.js`: `LEVEL_B` = the hand-written B list for each level (keyed by level id): sentences combining that level's topic with earlier ones. Loads before words.js., each a deck of English → Hebrew (nikud, tricky `wrong` answers, optional `hint` like the infinitive, optional `f:` = feminine version of an "I"/"we" line; `forMyGender()` picks per player). Levels are named 1A … 16A; `DECKS` adds the B levels 2B … 20B (the level's `LEVEL_B` list + `REVIEW_MIX` random A and earlier words; `mixReviewWords`) and review checkpoints ✅1–✅5 (`CHECKPOINTS`: after 5, 10, 13, 17, 20; `checkpoint: true`, ids `checkpoint-<level id without "level-">`; `CHECKPOINT_QUESTIONS` (30) spread evenly over every earlier level's A+B words; `mixCheckpointWords`; mastery = all those words, so checkpoint answers count toward the earlier levels too). Auto skips B levels and checkpoints while placing. `kind: "tense"` premade decks = "Key concepts" (past tense, future tense; more concepts can be added with the same kind), listed right after the themes. `number`/`numberHe` hold "3B"/"3ב". `TOPIC_DECKS` are ready-made decks with `kind: "theme"` (school, restaurant, trip) or `kind: "root"` (1–2 verb roots: infinitive, present, nouns from the root, and sentences where the same verb takes different words after it, e.g. מְדַבֵּר עִם / עַל; the wrong answers swap them) or `kind: "conj"` (one verb, 8 people × past + future, + 2 sentences; generated from a conjugation table, wrong answers = other tense / other gender / other person). Root + conj decks have `pattern` ("paal", "piel"…; list = `VERB_PATTERNS` in words.js): one pattern per deck (a root with two patterns = two decks), shown under one heading per pattern in the dashboard and lobby (`premadeSections()`; `sortPremadeDecks()` orders TOPIC_DECKS), plus an `icon`, called "Premade decks" in the lobby, listed only in class games (normal rooms show only Auto + levels, no premade or own decks), and never used by Auto. `WORDS` is the deck being played; `useDeck(id)` switches it. The host picks `auto` (default: each phone plays its own level, from `autoDeckId()` in `progress.js`) or one deck for everyone; the referee sends `deckId` in every snapshot.
- `progress.js`: flashcard memory (spaced repetition) and each player's Auto level (`noteAutoAnswer`; settings in `AUTO_LEVEL` in `rules.js`), saved on the phone, plus the account when logged in
- `account.js`: optional login (email + password, or an emailed sign-in link; 13+ checkbox to sign up). Typed email codes need custom SMTP so the Supabase email template can be edited and uploading progress to Supabase
- `supabase/setup.sql`: creates the `decks` and `progress` tables, their security rules, and the `delete_my_account()` function (paste into Supabase's SQL Editor)
- `decks.js`: the 🗂️ Deck dashboard ("אֵזוֹר הַחֲפִיסוֹת"; renamed from Teacher dashboard 2026-11-10: it is for teachers AND anyone who pays for more decks; logged-in only; free for now, later the paid door): a wide computer layout: "🏫 Host a class game" (calls `openPlayScreen(true)` in `game.js`) above 3 columns (My decks with ✏️ edit buttons, Premade decks, Levels incl. Auto). Clicking a row picks the class deck (`teacherPickId()`, saved as `golan-deck-v2`). "My decks" = make/edit/delete word lists saved in Supabase's `decks` table. The editor is a table (Hebrew | English | wrong answers with ➕, up to `DECK_LIMITS.maxWrong` | 🗑); Enter moves like a spreadsheet; pasting lines/tab-columns into a Hebrew box fills many rows (extra columns = wrong answers). Premade decks have 📋 "copy & edit" (keeps `f:` feminine versions while the Hebrew is unchanged). Leaving a Hebrew box auto-fills an EMPTY English box (`autoTranslateRow`; purple `auto-translated` until edited; never overwrites typed English; Hebrew sent as typed, since stripping nikud gave worse results). Saved words: `{ english, hebrew, wrong?, f? }`, tidied by `cleanDeckWords` in `words.js`. Decks register in `customDecks` (`words.js`, ids `custom-<db id>`) and show in the lobby picker under "My decks". The referee keeps a copy (`server.customDeck`) and sends it to phones as a `deck` event; a phone that's missing it sends `needDeck`. Limits in `DECK_LIMITS` (`rules.js`).
- `voice-test.html`: a tiny stand-alone page (not linked from the game) to check whether a phone's browser can talk at all. Buttons: plain "hello", en-US, Hebrew, after a game-style beep, voice list.
- `privacy.html`: the privacy page (its own page with its own styles, so it can scroll). Update it if the game starts saving something new.
- `quiz.js`: question popup (`openQuiz`). The shop opens it once per question an item costs (`startBuying` in `ctf-game.js`)
- `ctf-draw.js` (was `draw.js`): all Capture-the-Flag canvas drawing, including the minimap
- `network.js`: PeerJS room codes and messages
- **Games:** there will be exactly 3 games (Capture the Flag = `ctf`; Mt Hermon Racing = `race`; 1 more later). Each game = `<id>-server.js` (its referee rules) + `<id>-game.js` (its phone side) + its own drawing file, plugged into the shared files below. `server.mode` / `client.mode` = which game the room plays (picked on the modes screen, sent in every snapshot).
- `server.js`: the SHARED referee. Only the host runs it: rooms, players joining/leaving, teams in the lobby, the words, start (`serverStartGame`) and end (`serverEndGame(winner)`), back to the lobby after `WINNER_SCREEN_TIME`, snapshots 20 times a second. `serverReset(hostId, deckId, { classGame, mode })`: only a class game lets the host force a deck (`server.classGame`); a normal room is always `auto`. Everything game-specific goes through `serverGame()` = `SERVER_GAMES[server.mode]`, which answers `newRound`, `newPlayer(p)`, `playerLeaving(p)`, `startGame`, `handle(p, msg)` (any message that isn't a shared one), `update(dt)`, `snapshot(snap)`; `teams: false` = no blue/red teams (changes the "joined" message).
- `ctf-server.js`: Capture the Flag's referee rules: flags + score (`checkBase`: both flags in a team's circle = point), fighting, spear, throwing, pomegranates, berries, speed box. Registers `SERVER_GAMES.ctf` at the bottom.
- `game.js`: the SHARED phone code: screens, rooms, lobby, deck picker, joystick + keyboard, messages, `applySnapshot` (players + words), `changePhase`, `update`, `render`, `updateHud` (shared buttons), and the game loop (starts on `DOMContentLoaded`, so every game file has loaded). Everything game-specific goes through `phoneGame()` = `PHONE_GAMES[client.mode]`, which answers `resetTimers`, `clear`, `onKey`, `applySnapshot`, `onEvent`, `onPhase`, `update`, `render`, `updateHud(p, playing)`, plus lobby settings `teams: false` (one "Racers" list instead of blue/red) and `startText` (the Start button). Lobby parts marked `data-modes="ctf race"` in index.html only show for those games.
- `ctf-game.js`: Capture the Flag on the phone: shop, toolbar, weapons, throwing, frozen, flags, rocks, bumping, logs, berries, winner screen, moving my player, drawing the frame, its HUD chips/buttons. Registers `PHONE_GAMES.ctf` at the bottom.
- **Mt Hermon Racing** (`race`, steps 1–2 of 6 done + 2 visual reworks): ONE continuous downhill path from snowy Mt Hermon to the Kinneret (no laps; ~3 min), seen from behind (pseudo-3D: a row of short flat segments, projected near→far, then PAINTED far→near so hills and near things cover far ones). Settings in `RACE` (`rules.js`). `race-track.js` = the path (`TRACK.segments` with `width` (each piece planned as `pathWidth` (most), `wideWidth` or `narrowWidth` in `baseWidth`, then smoothed; exactly `gateWidth` at gates), hills and dips (smooth bumps added to the heights, size `RACE.hills`, kept away from gates), `gate` on the gate's own segment (the drawing needs it!), `snow` (ground melts from 12% to 40% of the way), `sand` (beach), `water` (the lake past the finish); built with `addRoad`/`downhill`; `TRACK.startZ`, `finishZ`, `gates` (`RACE.gateCount`, `gateGap` apart, each on a straight `gateZone`); sprites (bushes, oaks, olives, palms, basalt rocks, snow poles, reeds; no pines) placed with a seeded random so every phone matches; `findSegment` clamps, `trackProgress` 0..1). `race-draw.js` = `drawValley` (sky, clouds, far hills, patchwork fields far below, the Jordan, the Kinneret growing with progress, the mountainside under it), `drawRaceScene` (`clip` = highest screen point so far: pieces behind a hilltop are cut off at its line; `viewTurn` turns the camera: a constant `pan` plus moving the camera sideways so my sled stays centered), `drawSegment` (mountainside slopes dropping off the ridge, ground, path, start/finish checkers, lane lines only at gates), sprite pictures (painted once on hidden canvases), `drawSled` (a tiny 3D model turned by `turn`: wooden runners + slats, rider in a wool coat with a knitted kippah, tallit-striped scarf, tzitzit, Israeli flag), banners, `drawGate`, `drawRaceHud` (progress bar ⛰️→🌊 instead of laps). `race-server.js` = referee: grid start + countdown, accepts `move` (refuses impossible jumps), finish at `TRACK.finishZ`, ends when all finish or `waitAfterFirst` after the first. `race-game.js` = phone: hold left/right half (or arrows) to steer: `mySteer` = which way the sled points (swings toward the input at `turnSpeed`), and that moves it sideways; the view turns `cameraTurn` of the way with it; auto-forward, curves push outward, off the path (`|x| > segment.width`) = slow, solid sprites = crash, after the finish it brakes to a stop on the beach. A sled's `p.y` = distance along the path, `p.x` = sideways in `RACE.roadWidth` units. **Answer gates**: each phone picks its own word (`pickNextWord`) when a gate is `gateShowAt` segments ahead; English on the sign, right Hebrew + 2 wrong (`gateChoices` via `buildChoices`) over the 3 lanes; the lane you're in when you pass (`laneAt(x, gateWidth)`) is your answer → `recordAnswer` + `autoLevelAnswer` (time = when you settled into your final lane); right = boost, wrong = slowed, off the path = missed (not saved). A compact question panel at the top repeats it and fades out just before the gate.

## Conventions
- Write beginner-friendly comments, and explain every change in plain English.
- Settings belong in `rules.js`, not scattered through the code.
- Gameplay decisions go in the referee (`ctf-server.js` for Capture the Flag). Each phone moves only its own player and asks the referee for everything else.
- Shared code (`server.js`, `game.js`) never calls a game's functions directly; it asks `serverGame()` / `phoneGame()`. A game's files may use the shared functions.
- `index.html` loads the scripts in order (map → rules → sound → speech → levels-b → words → progress → account → decks → quiz → ctf-draw → race-track → race-draw → network → server → ctf-server → race-server → game → ctf-game → race-game). Each game's files go right after the shared file they plug into. Keep it that way.
- Action buttons use `pointerdown` so they work while a finger is on the joystick. Grab and Shop call `resetStick()`, so the player stops. Hit and Drop don't.
- Show player names with `textContent`, never `innerHTML`.
- **Hebrew first, everywhere: Hebrew on top (bigger), English underneath (smaller)**, to get players reading Hebrew first. The one exception is the lobby's level list (one line per option, "English · Hebrew"). In HTML use `<span class="he" lang="he" dir="rtl">…</span><span class="en">…</span>` (Hebrew span FIRST). In JS use `setBilingual(el, en, he)` (in `rules.js`), `showToast(en, he)`, or `toast(en, he, to)` in the referee. The one exception is the English word in the quiz, because its Hebrew is the answer.
- Screens: home (masculine/feminine, Play Game / Log in / 🗂️ Deck dashboard) → play (nickname, create/join; class games hide join) → modes (pick a game: Capture the Flag + 2 "coming soon") → lobby → game → winner → back to lobby. Leaving uses the `leave-confirm` popup. Messages pop up at the bottom; the word card sits at the very top.
- Two kinds of rooms: **normal** (from Play Game): each phone picks its own level in the lobby (`golan-my-level`, default Auto). **Class game** (from the dashboard): the host picks for everyone (`golan-deck-v2`). `playedDeckId()` in `game.js` decides which deck a phone plays. The lobby picker sits under the room code and is our own dropdown (`deck-dropdown-*`, drawn from the hidden `<select id="deck-select">`), because phones' built-in lists cover the whole screen.
- Keep file names lowercase, because GitHub Pages is case-sensitive.
